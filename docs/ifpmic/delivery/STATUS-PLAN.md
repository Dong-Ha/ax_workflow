# 진행 현황판 — 작은 전달 계획

- 목적: 현재 볼 수 있는 결과, 전체 완료율, 남은 장애와 다음 데모를 한 화면에서 확인한다.
- 대상: `delivery/status.html`, 데스크톱/모바일 캡처, `progress.json`, `AGILE-DELIVERY.md`, `RESUME.md`, 주기03 현황. 제품 실행기·기존 UI·동결 계약은 수정하지 않는다.
- 방법: 기존 두 화면은 HTTP 응답만 확인한다. 새 현황판은 기존 전달 캡처와 정적 상태를 사용하며 브라우저로 데스크톱/모바일, 이미지·링크·가로 넘침·오류·외부 요청을 확인한다. 기준 JSON의 verified 단계 수와 표시 수치를 대조하고 attempt02의 세 장애를 반영한다.
- 담당: Code-dev 작성/통합/브라우저 확인, TC Agent가 계획과 최종 산출물의 사실 관계를 검토한다.
- 합격 기준: 2/16=12.5%, 전달된 두 부분 흐름, 미완료 실행 연동, 현재 세 장애가 정확하다. 모의 재생/실제 저장/미완료 실행을 구분한다. 정상 화면·작은 화면·미완료 상태·기존 링크 회귀를 확인한다. 새로운 업무 기능 완료 주장은 없다.
- 예상 결과: 사용자가 바로 열 수 있는 정적 진행 현황판과 대화에서 볼 수 있는 캡처. 다음 데모는 저장 요청→실제 접수→동일 run/receipt·QUEUED이며 정상·중복·권한·새로고침을 완료 기준으로 고정한다.
- 증빙: 공개 화면과 정제된 브라우저 결과 JSON, 기존 결과/검토 링크, 커밋·push. 원본 업로드와 private 실행 자료는 공개하지 않는다. 캡처의 과거 화면임과 상태 기준 날짜를 표시한다.
- 실패 복구: 잘못된 수치·링크·레이아웃만 수정해 관련 브라우저 확인을 반복한다. 제품 소스/계약을 변경하거나 실제 full490을 실행해 현황판을 맞추지 않는다. 이 문서는 H2 실행 승인이나 기존 검증 의무 변경이 아니다.

진행 제한: 동시에 구현하는 사용자 흐름은 하나. 매 세션마다 화면 변화 또는 새 기능 없음을 먼저 보고하고, 해결 못한 장애와 다음 행동을 기록한다. 내부 검증 수를 전체 완료율로 환산하지 않는다.
