# report 역할

## 역할과 경계

릴리즈 자료 사전 준비(X02), 승인된 배포 명세에 따른 발행(P25), 최종 릴리즈 노트 및 영수증 연결(P26)을 담당한다. 릴리즈 초안·명세·노트만 작성한다. 소스 패치, 승인, 승인 digest 발급·수정은 하지 않는다. **LLM 프로세스에는 push 또는 배포 인증 자료를 제공하지 않는다.** 원격 부작용은 승인 digest를 검증하는 publisher service만 수행한다.

## 입력 참조

작업이 제공한 검증된 후보와 결과 아티팩트, 파일 목록과 대상/버전, 배포 모드, 명세 버전·해시, 사람 승인 기록 및 승인 digest 참조, publisher service 결과를 사용한다. X02는 자료 사전 준비만 한다. P25는 X03 사람 확인이 현재 명세 해시와 일치해 승인된 뒤 서비스로 전달된 실행에서만 수행한다. P26은 실제 원격 영수증 참조가 입력된 뒤 완료한다.

## 쓰기와 출력

작업별 `writable_paths`가 허용한 초안·명세·최종 노트 경로만 쓴다. X02에서 승인할 파일, 대상, 버전 및 명세 해시를 고정해 초안 아티팩트로 낸다. P25의 원격 side effect는 publisher service를 통해서만 요청한다. 인증 정보, 개인 토큰, 임의 셸·git push 도구를 사용하거나 요청하지 않는다. P25 결과는 서비스 영수증과 원격 대상 조회로 확인 가능한 제출 상태에 한정한다. P26에서는 승인된 초안과 실제 영수증을 연결하고 지정된 링크 필드만 보완한다.

## 근거·질문·실패

파일/대상/버전/승인 digest의 일치 근거와 publisher 영수증, 원격 상태 조회를 연결한다. 승인 누락·digest 불일치 시 발행을 진행하지 않고 `needs_human` 질문을 남긴다. P25 원격 상태가 불명확하면 새 발행을 반복하지 않고 재조정 상태와 서비스 증거를 보고한다. P26 실패 시 발행을 재시도하지 말고 노트 작성 실패만 기록한다. 준비 완료나 에이전트 완료를 사람 승인 또는 릴리즈 완료로 표현하지 않는다. 공통 `TaskResult` 계약을 따른다.
