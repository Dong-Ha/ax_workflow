# 로컬 출시 관찰 및 롤백 계획

현재 단계: environment. test-environment.md의 준비 기준과 최신 제품 계약을 따른다. 운영팀은 계획만 작성하며 컨트롤러가 후속 승인된 실행에서 테스트 서버, 패키징 및 상태 점검을 담당한다. 현재 서버 시작·패키징·배포·상태 점검·네트워크 요청·커밋·push는 수행하지 않았다.

## 출시 게이트와 순서

1. 제품부가 요구사항 보완과 최신 계약에 맞춰 기존 대기/완료 표현 및 기본 선택 관련 문서 충돌을 정합화한다.
2. 개발팀이 상태 계약 결함과 QA 결함을 수정한다. 서버·어댑터·인증·API 동작 및 원본 기록 변경은 허용하지 않는다.
3. QA가 후보 ID에 연결된 단위·브라우저 테스트에서 6개 상태 키/정확한 문구, 공급자/세션 초기화와 선택 안내, 선택 삭제 이용 불가 상태를 모두 검증한다. F01–F09/P01–P06 전체, 관련 회귀와 타입 검사 및 변경 경계 검토 증거를 확보한다. 실패하면 개발팀으로 반환하고 같은 사례와 영향 범위를 재검증한다.
4. 출시 차단 및 주요 결함을 해결하고 필수 미실행/차단 검증 공백을 해소한다. 기존 전체 npm test 실패의 원인과 허용 범위 판정을 기록한다. 금지된 실행을 강행하거나 테스트를 제거해 성공으로 보고하지 않는다.
5. 제품부·QA 검토 및 명시적 출시 승인 기록을 후보 ID에 연결한다. 이전 검증된 로컬 버전의 패키지·체크섬·호환성 및 복구 가능 여부를 확보한다. 복구 대상이 없으면 배포를 시작하지 않는다.
6. 컨트롤러가 별도 허용된 단계에서 승인된 후보를 패키징하고 후보/패키지 체크섬 연결을 검증한다. 운영팀이 승인된 로컬 배포를 진행하며 컨트롤러가 시작과 상태 점검을 수행한다. 승인 뒤 후보가 바뀌면 재검증·재승인한다.
7. 운영팀은 아래 관찰을 검토하고 성공 또는 롤백 결과를 기록한다. 모든 조건 충족 전에는 출시 완료로 표시하지 않는다.

현재 E01 상태 충돌, 필수 브라우저 증거 부재 및 전체 테스트 실패가 남아 있어 출시 게이트는 BLOCKED다. 이전 구현 보고서의 부분 통과를 현재 후보의 출시 승인으로 간주하지 않는다.

## 출시 관찰

관찰은 컨트롤러가 허용된 로컬 합성 환경에서 수집하는 결과 요약으로 수행한다. 실제 대화 기록이나 인증 자료를 관찰 입력으로 사용하지 않는다. 현재 단계는 점검 요청을 보내지 않으며 관찰 기간 동안 외부 요청도 추가하지 않는다.

| 확인 시점 | 통과 조건 | 실패 시 처리 |
| --- | --- | --- |
| 시작 직후 | 승인한 후보/패키지 ID 일치, localhost 전용 실행, 컨트롤러 상태 점검 성공, 화면 로드 성공 | 후보 노출 중지 후 롤백 |
| 초기 기능 확인 | all/전체, inProgress/진행 중, completed/턴 완료, failed/실패, interrupted/중단, unknown/상태 미확인; unknown 대기 해석 없음 | 계약 결함으로 개발팀 반환 및 롤백 |
| 검색·필터 조작 | 네 필드 검색과 AND, 맥락 조상·일치 후손, 전체 기준 집계, 초기화와 빈 결과 | 실패 사례 기록 및 롤백 |
| 범위 전환·삭제 | 숨긴 유효 선택 상세 유지; 공급자/세션 변경은 필터·이전 상세 제거 및 선택 안내, 자동 선택 없음; 삭제는 이용 불가 안내 | 이전 상세 노출 또는 상태 전이 결함으로 롤백 |
| 갱신 및 접근성 | 같은 범위 갱신과 지연 응답 처리, 이전 턴 결과 제외, 페이지/집계 독립, 키보드 및 좁은 화면 조작 | 결함 반환 및 롤백 |
| 안전성 | 프로젝트 혼입·민감 표식·추론/원시 명령/도구 입출력/인증 노출 없음, 원본 쓰기 및 추가 검색 요청 없음 | 즉시 관찰 중단·후보 중지·롤백 |

관찰 종료 조건은 위 항목 전부 통과, 최소 한 번의 같은 범위 갱신과 공급자·세션 각각의 전환/선택 삭제 확인, 미해결 출시 차단·주요 결함 없음이다. 시작 점검과 관찰 종료 때 컨트롤러가 상태를 확인하고 운영팀은 후보 ID, 시점, 항목별 판정, 결함 ID만 기록한다. 수치 관찰 기간은 컨트롤러의 실행 계획에 기록하며 확인 전 임의로 경과했다고 주장하지 않는다.

## 롤백 순서

1. 상태 점검 실패, 패키지 불일치, 핵심 계약 위반, 민감 노출 또는 프로젝트 혼입이 발견되면 출시 완료 판정을 중단한다. 실패 후보 ID·결함 ID·영향 요약을 남기고 원시 자료는 복사하지 않는다.
2. 컨트롤러가 실패 후보의 로컬 실행과 진행 중인 관찰을 중지한다. 원본 기록·설정·인증 파일은 복구 대상으로 삼지 않는다.
3. 사전에 기록한 이전 검증 패키지의 ID와 체크섬을 확인한다. 검증된 대상이 없거나 일치하지 않으면 실행을 중지 상태로 유지하고 운영 장애로 보고한다. 임의 버전으로 대체하지 않는다.
4. 운영팀이 후속 허용 범위에서 기존 로컬 배포 절차로 이전 패키지를 복원하고 컨트롤러가 시작한다. 데이터 마이그레이션·서버 변경·의존성 설치 없이 UI 패키지를 복구한다. 브라우저는 복구 버전으로 새로 로드하여 실패 후보의 일시 선택/필터 상태를 제거한다.
5. 컨트롤러 상태 점검과 합성 핵심 조작으로 복구 버전 식별, 화면 로드, 범위 전환 시 이전 상세 비노출 및 개인정보 경계를 확인한다. 복구 검증도 실패하면 중지 상태를 유지하고 운영팀에 에스컬레이션한다.
6. 실패 후보와 복구 후보/패키지 ID, 복구 판정, 남은 영향 및 결함 반환을 기록한다. 개발 수정 → QA 동일 사례/영향 범위 재검증 → 제품·QA 검토 → 새 출시 승인 → 컨트롤러 재패키징 순서로 재출시한다.

## 최종 기록

test-environment.md의 버전 양식에 승인 시점, 배포 후보와 이전 패키지 연결, 시작/종료 관찰 판정, 롤백 여부 및 복구 결과를 추가한다. 환경 값·자격 증명·API 응답·원시 명령 출력은 기록하지 않는다. 현재 결과는 문서 준비 완료, 실행 NOT RUN, 출시 BLOCKED, 배포 및 롤백 미실행이다.
