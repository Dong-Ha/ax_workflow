# 에이전트 검색·상태 필터 상호작용 프로토타입

현재 단계: requirements. 실행 가능한 UI가 아닌, 개발 및 조직 검토용 상호작용 명세다. 모든 이름·ID·관계는 합성 예시이며 실제 기록을 사용하지 않는다. 수용 기준은 requirements.md의 ID를 따른다.

## 화면 구성

상단에는 공급자 및 세션 선택을 둔다. 그 아래에 검색 입력(레이블: 에이전트 검색, 안내: 이름, ID, 원본 역할 또는 한국어 역할), 상태 단일 선택(전체 / 진행 중 / 완료 / 실패 / 대기), 필터 초기화 버튼을 둔다. 검색 입력값을 바꾸거나 상태를 선택하면 추가 제출 없이 현재 스냅샷에 조건을 적용한다.

필터 아래에는 `일치 6 / 전체 6`과 전체 스냅샷 상태 집계 `진행 중 2 · 완료 1 · 실패 1 · 대기 2`를 표시한다. 활성 조건은 `검색: developer · 상태: 실패`처럼 텍스트로 확인할 수 있다. 초기화 버튼은 조건이 없으면 비활성화하고, 조건이 있으면 활성화한다.

목록 영역은 기존 에이전트의 부모·자식 들여쓰기를 유지한다. 각 카드에는 안전 처리된 이름, ID, 원본 역할과 한국어 표시 역할, 상태 텍스트를 표시한다. 비일치 조상에는 `맥락 · 일치하는 하위 에이전트의 상위 항목`을 표시한다. 맥락 카드도 선택 가능하다. 선택 카드에는 선택 표시를 제공하며 색상만으로 선택·상태·맥락을 구분하지 않는다.

넓은 화면에서는 목록 옆에 선택 상세를 유지하고, 좁은 화면에서는 같은 화면의 목록 아래에 상세를 배치한다. 필터 때문에 상세 영역을 제거하지 않는다. 선택이 없으면 `에이전트를 선택하면 상세를 볼 수 있습니다`를 표시한다. 상세는 기존 공개 가능한 정보만 사용하며 원시 기록이나 민감 필드를 추가하지 않는다.

## 합성 스냅샷

| ID | 이름 | 원본 역할 | 한국어 표시 역할 | 상태 | 실제 부모 |
| --- | --- | --- | --- | --- | --- |
| lead-1 | Atlas Lead | orchestrator | 조정자 | 진행 중 | 없음 |
| dev-1 | Build Agent | developer | 개발자 | 진행 중 | lead-1 |
| qa-1 | Check Agent | tester | 테스트 담당자 | 대기 | dev-1 |
| review-1 | Review Agent | reviewer | 검토자 | 완료 | 없음 |
| dev-2 | Patch Agent | developer | 개발자 | 실패 | review-1 |
| ops-1 | Local Operator | operator | 운영자 | 대기 | 없음 |

역할 번역은 상호작용 검토용 예시다. 구현은 기존 역할 표시 체계를 사용하며 원본 역할 문자열과 실제 한국어 표시 문자열을 모두 검색 대상으로 삼는다.

## 구체적 상호작용 흐름

### A. 초기 화면과 필드 검색

공급자 A의 세션 S1을 열면 검색은 빈 값, 상태는 전체다. 6개 카드와 `일치 6 / 전체 6`을 표시한다. 목록은 lead-1 → dev-1 → qa-1, review-1 → dev-2, ops-1 관계를 보여준다.

사용자가 Build를 입력하면 dev-1이 일치하고 lead-1은 맥락으로 표시된다. qa-1은 숨긴다. 집계는 `일치 1 / 전체 6`이다. 검색어를 dev-2로 바꾸면 dev-2가 일치하고 review-1이 맥락으로 표시된다. developer 또는 개발자를 입력하면 dev-1과 dev-2가 일치하고 두 부모가 맥락으로 표시된다. 집계는 `일치 2 / 전체 6`이며 화면에는 총 4개 카드가 있다. 이는 F01, F03, F04의 예시다.

### B. 검색과 상태 결합

검색 developer 상태에서 실패를 선택한다. dev-2만 일치하고 review-1은 맥락으로 남는다. `일치 1 / 전체 6` 및 전체 상태 집계는 유지한다. dev-1은 역할이 일치해도 상태가 달라 숨겨진다.

검색을 테스트, 상태를 대기로 바꾸면 qa-1만 일치한다. lead-1과 dev-1은 맥락 카드이며 전체 경로가 펼쳐진다. review-1, dev-2, ops-1은 숨긴다. 일치 수는 1이며 화면 카드 수 3과 구분한다. 이는 F02–F04의 예시다.

### C. 필터가 숨긴 선택 상세

초기화 후 dev-1을 선택한다. 상세에 Build Agent가 표시된다. 검색 developer + 실패를 적용하면 목록에는 review-1과 dev-2만 보이지만 Build Agent 상세는 계속 표시한다. 상세 상단에 `선택한 에이전트가 현재 필터에서 숨겨져 있습니다`와 `필터 초기화` 동작을 제공한다. 집계는 여전히 1 / 6이다.

상세의 초기화를 실행하면 검색은 빈 값, 상태는 전체로 돌아가고 6개 카드가 보인다. dev-1 선택은 유지한다. 숨김 안내는 사라진다. 맥락 review-1을 선택하면 해당 상세로 전환되며 맥락 카드도 일반 카드와 같은 선택 동작을 제공한다. 이는 F05, F06의 예시다.

### D. 일치 없음과 빈 세션

검색 no-such-agent를 입력하면 목록에 `조건에 맞는 에이전트가 없습니다`와 `필터 초기화`를 표시한다. 집계는 0 / 6이다. 기존 선택이 있으면 상세와 숨김 안내를 유지한다. 초기화 버튼으로 전체 목록을 복구할 수 있다.

빈 세션에서는 `이 세션에 표시할 에이전트가 없습니다` 및 0 / 0을 표시한다. 필터 결과 없음과 세션 자체가 비어 있음을 구별한다. 이는 F04–F06의 예시다.

### E. 공급자·세션 변경과 갱신

검색과 상태가 적용된 상태에서 공급자 B 또는 세션 S2로 변경하면 검색은 빈 값, 상태는 전체가 된다. 기존 선택 상세를 제거하고 선택 안내를 표시한다. 새 스냅샷을 기다리는 동안 이전 세션 카드나 집계를 새 세션 결과로 보여주지 않는다.

같은 공급자 A / 세션 S1이 갱신되면 검색·상태·존재하는 선택을 유지한다. 예를 들어 dev-2 상태가 실패에서 완료로 변경되면 developer + 실패 결과는 0 / 6이 된다. 전체 상태 집계는 진행 중 2 · 완료 2 · 실패 0 · 대기 2로 변경된다. dev-2가 선택되어 있었다면 갱신된 상세 및 필터 숨김 안내를 표시한다. 선택 에이전트가 스냅샷에서 제거되면 기존 내용을 지우고 `선택한 에이전트를 더 이상 이용할 수 없습니다`를 표시한다. 이는 F07, F08의 예시다.

## 접근성 및 검토 체크포인트

- 탭 순서는 공급자 → 세션 → 검색 → 상태 → 활성화된 초기화 → 표시 카드 → 상세의 동작 순으로 둔다. 카드 선택은 Enter 또는 Space로 가능하며 명확한 포커스 표시를 제공한다.
- 검색·상태 변경으로 입력 포커스를 이동시키지 않는다. 결과 수 갱신은 보조 기술에 비방해 방식으로 알린다. 숨김 안내와 맥락 배지는 텍스트로 읽을 수 있다.
- 제품부는 원본/한국어 역할 검색, AND 결합, 맥락 배지, 전체 집계, 숨겨진 선택 상세, 공급자·세션 초기화 흐름을 검토한다.
- 개발팀은 기존 안전 텍스트·스냅샷 모델을 사용한다. 테스트팀은 합성 자료로 requirements.md의 수용 기준을 검증하고 결함을 개발팀으로 반환한다. 운영팀의 로컬 배포는 출시 승인 후 후속 단계에서 진행한다.

이 단계에서는 제품 코드, 테스트 코드, 서버 또는 어댑터를 수정하지 않았으며 기능 검증·출시 승인을 수행한 것으로 간주하지 않는다.
