# 에이전트 모니터링 대시보드 상세 설계

현재 단계: design. 입력은 requirements.md의 F01–F09, P01–P06과 prototype.md다. 이 문서는 후속 개발·QA의 구현 기준이며 제품 구현, 테스트 실행, 출시 승인 또는 배포 결과가 아니다.

## 범위와 현재 구조

기존 src/App.tsx는 공급자·세션 선택, 전체 Dashboard 스냅샷 폴링, 부모별 트리, 선택 상세, 활동 페이지 처리를 담당한다. src/styles.css는 화면 배치를 담당한다. 후속 개발은 이 프런트엔드 경계에서 검색과 상태 필터를 추가하고 필요한 순수 계산을 src/ 내부 모듈로 분리한다. 기존 읽기 전용 API, 요청 형식과 폴링 주기는 유지한다.

server/, 어댑터, 인증, 원본 기록, 서버 상태 판정, 프로젝트 범위와 API 계약은 변경하지 않는다. 검색을 위한 추가 요청, 외부 패키지, 실제 기록 접근, 네트워크 실행, 영구 저장은 범위 밖이다. 단계 산출물은 이 문서, development-plan.md, development-rules.md 세 개뿐이다.

## 상태와 역할 표현의 결정

현재 AgentStatus는 inProgress, completed, failed, interrupted, unknown이며 waiting은 없다. 현재 roleNames도 한국어 번역이 아닌 영문 배지 중심이다. 이 차이를 서버 변경이나 기록 추정으로 해소하지 않는다.

상태 선택값은 all, inProgress, completed, failed, waiting 다섯 개로 제한한다. 대기의 프런트엔드 분류를 다음과 같이 제안한다. 이는 서버 상태를 재판정하는 규칙이 아니며 제품부가 개발 착수 전에 확인해야 할 의미 결정이다.

| 필터 문구 | 기존 모델 조건 | 카드의 상태 의미 |
| --- | --- | --- |
| 전체 | 제한 없음 | 기존 상태 텍스트 유지 |
| 진행 중 | status === inProgress | 저장된 진행 중 상태 |
| 완료 | status === completed | 턴 완료이며 과제 전체 완료를 보장하지 않음 |
| 실패 | status === failed | 저장된 실패 상태 |
| 대기 | status === unknown | 확정 상태 확인 대기; 상태 미확인이라는 원래 카드 문구 유지 |

interrupted는 중단으로 표시하고 전체에서만 일치한다. unknown을 실행 대기나 사용자 입력 대기로 단정하지 않는다. stale, 무활동 시간, 닫힌 edge, 결과 텍스트 유무로 상태를 변경하지 않는다. 전체 상태 요약에는 중단과 상태 미확인도 포함해 N과의 합계가 일치하도록 한다. 대기 필터의 안내에는 “확정 상태 확인 대기(상태 미확인)”를 제공한다. 제품부가 이 분류를 수용하지 않으면 의미 결함으로 반환하고, 서버 변경 없이 표현 가능한 기준을 확정한 뒤 개발·QA를 진행한다. 출시 전에 해결되어야 하며 대기 기능이 이미 검증되었다고 보고하지 않는다.

역할은 공통 순수 함수로 원본 role, 기존 영문 배지, 한국어 표시 문구를 함께 얻는다. 기본 한국어 문구는 main/orchestrator=조정자, worker=워커, worker_luna=워커 · 루나, senior_sol=선임 · 솔, expert_astra=전문가 · 아스트라다. 합성 계약 예시의 developer=개발자, tester=테스트 담당자, reviewer=검토자, operator=운영자도 지원한다. 미등록 역할은 안전한 원본 문자열을 표시·검색에 사용하며 임의 번역을 만들지 않는다. 카드에는 원본 역할과 한국어 표시 문구를 확인할 수 있게 한다. 영문 배지를 유지하면 검색에도 포함할 수 있지만 계약의 네 필드를 대체하지 않는다.

## 컴포넌트와 데이터 흐름

| 책임 단위 | 입력 | 출력·책임 |
| --- | --- | --- |
| App / 세션 상태 관리 | 기존 Dashboard, 공급자·세션 선택 | 현재 범위 스냅샷, 필터 상태, 선택 ID, 요청 세대 관리 |
| AgentFilterControls | query, status, 활성 여부 | 검색·단일 상태 선택·초기화 이벤트; 명시적 레이블 |
| 순수 필터 계산 모듈 | 전체 agents, 정규화된 조건, 역할 표시 함수 | 고유 ID 맵, 일치 ID, 표시 ID, 맥락 ID, 전체 집계 |
| AgentFilterSummary | M, N, 전체 상태 집계, 조건 | 일치/전체와 활성 조건 표시, 비방해 접근성 알림 |
| AgentTree / 카드 렌더러 | 기존 순서·관계, 표시/맥락 ID, 선택 ID | 일치 카드와 실제 경로의 맥락 카드, 카드 선택 이벤트 |
| AgentDetail / 기존 상세 영역 | 전체 맵에서 선택 ID로 얻은 최신 agent | 기존 상세, 필터 숨김 안내, 제거 안내, 초기화 이벤트 |
| EmptyState | 로딩·오류·N·M 상태 | 연결 중, 데이터 오류, 빈 세션, 결과 없음의 구별 |

위 이름은 책임 경계다. 작은 컴포넌트를 불필요하게 각각 파일로 분리하지 않는다. 재사용되는 역할·필터 계산은 예를 들어 src/agent-filter.ts로 분리하고, 기존 상세/카드 렌더러는 필요한 범위만 수정한다.

데이터는 기존 읽기 전용 응답 → 현재 범위 검사 → 전체 고유 agents 맵 → 전체 집계 및 일치 판정 → 조상 경로 합집합 → 트리 표시로 흐른다. 상세는 전체 맵에서 직접 조회한다. 활동 items와 nextCursor는 별도 흐름이며 필터·에이전트 집계의 입력이 아니다. 검색은 nickname(이름), id, role, 실제 한국어 표시 역할만 필수 입력으로 사용하고 task/result/activity는 검색하지 않는다.

## 필터와 계층 계산

1. query를 trim 후 소문자로 정규화한다. 각 검색 대상도 동일하게 소문자화하여 부분 문자열을 검사한다. 내부 공백은 유지하고 단어 분해·정규식·초성 검색을 추가하지 않는다. 빈 query는 모든 에이전트와 일치한다.
2. 전체 스냅샷의 고유 ID마다 `검색 일치 AND 상태 일치`를 계산해 matchedIds를 만든다. M은 이 집합 크기, N은 전체 고유 맵 크기다. 상태별 집계 역시 전체 맵에서 계산한다.
3. matchedIds에서 시작하여 기존 parentId를 따라 전체 맵에 존재하는 조상을 visibleIds에 더한다. 각 경로 방문 집합으로 순환을 차단한다. missing parent에서는 종료하며 다른 세션이나 프로젝트에서 부모를 찾지 않는다.
4. contextIds는 visibleIds에서 matchedIds를 뺀 값이다. 부모가 일치해도 불일치 후손·형제를 자동으로 포함하지 않는다. 각 노드는 한 번만 렌더링한다. 원래 스냅샷의 루트·형제 순서를 유지한다.
5. parentId를 관계 기준으로 사용한다. edges.closed를 완료 근거로 사용하거나 새 부모를 구성하지 않는다. 기존의 부모 누락 루트 처리를 유지하고, 필터에서 사라진 부모를 새 루트로 바꾸는 대신 실제 조상 경로를 보존한다.
6. 일치 후손까지의 경로는 항상 펼쳐 보인다. 현재 UI에는 접기 상태가 없으므로 새 접기 기능을 추가하지 않는다. 향후 접기 도입 시 활성 필터의 일치 경로 표시를 우선한다.

고유 맵·부모 맵은 스냅샷이 바뀔 때 재계산하고, 일치·맥락 집합은 스냅샷 또는 조건이 바뀔 때 계산한다. 조상 경로는 이미 처리한 경로에서 멈춰 중복 작업을 줄인다. 원본 배열·객체는 수정하지 않는다. 잘못된 순환으로 재귀가 멈추지 않거나 집계가 중복되지 않도록 방어하되 합성 관계나 원본 데이터 수정을 만들지 않는다.

## 선택과 수명 주기

선택은 selectedAgentId와 선택 상태(없음/존재/제거됨)로 관리하고, 객체 사본을 보관하지 않는다. 필터 결과에서 선택을 찾거나 필터 갱신 때 첫 결과를 자동 선택하지 않는다. 현재 fetchDashboard의 첫 에이전트 자동 선택·사라진 선택 대체는 변경 대상이다.

| 사건 | 필터 | 선택·상세 | 스냅샷·활동 |
| --- | --- | --- | --- |
| 최초 진입 | 빈 검색, 전체 | 선택 안내 | 해당 범위 로딩 표시 |
| 검색·상태 변경 | 새 조건 | 동일 ID 유지 | 추가 요청·활동 초기화 없음 |
| 초기화 | 빈 검색, 전체 | 동일 ID 유지 | 전체 목록 복구 |
| 맥락 카드 선택 | 유지 | 해당 ID의 최신 상세 | 기존 선택 변경 활동 흐름 사용 |
| 같은 세션 갱신 | 유지 | 존재하면 최신 데이터, 제거되면 이용 불가 안내 | 전체 집계·필터 재계산 |
| 공급자 또는 실제 세션 변경 | 즉시 초기화 | 선택 및 제거 안내 초기화 | 이전 카드·집계·활동·cursor 제거, 새 범위 로딩 |

선택 agent가 visibleIds에 없을 때만 “선택한 에이전트가 현재 필터에서 숨겨져 있습니다”와 초기화 동작을 표시한다. 맥락으로 보이는 선택에는 맥락 안내를 사용한다. 상세 표시를 위해 visibleIds나 M을 증가시키지 않는다. 제거된 ID는 안내용으로만 유지하고 이전 task/result/activity 내용은 지운다. 다른 에이전트로 자동 대체하지 않는다. 동일 ID가 같은 범위에서 다시 나타나면 최신 데이터로 상세를 복구할 수 있다.

범위 키는 provider와 실제 selectedSessionId의 쌍이다. 사용자 선택 변경뿐 아니라 서버 응답이 실제 세션을 변경한 경우도 동일 전이로 처리한다. 초기 기본 세션 결정은 선택 없는 로딩 상태에서 새 범위를 확정한다. 범위 변경은 이벤트에서 즉시 상태를 지우고 이전 요청 세대를 무효화한다. 폴링과 활동 요청의 응답을 범위 키 및 요청 세대로 확인하여 늦은 이전 응답이 상태를 덮지 못하게 한다. 같은 범위의 갱신은 범위 변경으로 취급하지 않는다.

선택 제거·범위 변경 시 활동 요청도 무효화하고 활동 목록, cursor, 오류, 이전 페이지 로딩 상태를 정리한다. 필터로 숨긴 선택은 유효한 같은 범위의 선택이므로 기존 상세·활동 조회를 유지한다. 갱신된 result가 비어 있으면 이전 result를 병합하지 않는다. 턴의 종료·새 요청 판정은 서버가 제공한 현재 안전 필드만 사용한다.

## 화면과 접근성

공급자·세션 아래에 검색, 상태, 초기화를 배치한다. 검색 또는 전체 이외 상태가 활성화되면 초기화가 활성화된다. 검색 변경에 제출이나 포커스 이동을 요구하지 않는다. 집계는 항상 “일치 M / 전체 N”이며 상태 요약도 필터 전 전체 기준이다. 로딩 중에는 이전 수를 새 세션 집계로 표시하지 않는다.

N>0, M=0이면 조건 결과 없음과 초기화를 표시한다. N=0인 유효 스냅샷이면 빈 세션과 0/0을 표시한다. 로딩과 오류를 빈 세션으로 표현하지 않는다. 상세는 두 빈 결과 상태에서도 독립적으로 유지하거나 제거 안내를 제공한다.

넓은 화면은 기존 목록/상세 병렬 배치, 좁은 화면은 같은 화면에서 목록 아래 상세 배치를 유지한다. 검색 컨트롤은 줄바꿈되며 긴 ID·역할은 영역 안에서 줄바꿈한다. 원본 역할과 한국어 역할, 상태, 맥락, 선택은 텍스트로 식별 가능해야 한다.

검색 입력과 상태 select에 연결된 label을 제공한다. 카드와 초기화는 native button을 사용하고 카드에 aria-pressed를 유지한다. 결과 요약은 role=status 또는 aria-live=polite로 알리되 전체 트리를 live 영역으로 만들지 않는다. 검색·상태 변경 시 포커스를 유지하고 명확한 focus-visible 스타일을 제공한다.

## 격리와 검증 인계

기존 서버의 safeText 처리로 공개된 문자열만 사용한다. 프런트엔드에서 원시 기록을 다시 읽거나 민감 필드를 API/검색/상세에 추가하지 않는다. React 텍스트 렌더링을 사용하고 HTML 주입을 금지한다. 서버 격리로 제외된 루트·관계는 UI에서 복구하지 않는다. 프런트엔드는 스냅샷에 없는 프로젝트 정보를 자체 추정할 수 없다.

prototype.md의 N=6 자료는 개념적 합성 스냅샷이다. QA는 실제 모델에 맞춰 한국어 역할 표시 함수와 승인된 대기 분류를 연결한다. 활동 페이지 크기·필터 카드 수를 N으로 계산하지 않는다. 현재 Dashboard.agents에는 페이지 계약이 없으므로 에이전트 페이지 API를 추가하지 않는다.

F01/F02는 필드별 검색·AND, F03은 조상 맥락과 숨긴 형제, F04는 M/N와 전체 상태 집계, F05는 초기화·두 빈 상태, F06은 독립 상세, F07/F08은 범위 전이·갱신·늦은 응답·선택 제거, F09는 키보드·접근성으로 인계한다. P01–P06은 변경 경계, 합성 격리 자료, 민감 표식 비노출, 검색 비영구성, 보고서 최소 공개를 확인한다. 구현 및 검증 순서는 development-plan.md를 따른다.
