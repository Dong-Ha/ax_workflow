# 에이전트 모니터링 대시보드 개발 계획

현재 단계: design. requirements.md와 prototype.md를 입력으로 상세 설계 및 후속 작업 순서를 정의한다. 제품 코드와 테스트 코드는 이번 단계에서 작성하지 않는다.

## 단계와 책임

제품부 → 개발팀 → 테스트팀 → 운영팀 순서로 인계한다. 제품부는 요구사항과 표현의 의미를 확인하고, 개발팀은 UI 구현·결함 수정, 테스트팀은 독립 검증·결함 보고, 운영팀은 출시 승인 후 로컬 배포를 담당한다. 결함은 개발팀으로 반환하고 수정 후 테스트팀이 재검증한다. 설계 완료를 구현 완료·검증 통과·출시 승인으로 간주하지 않는다.

## 개발 착수 전 확인

- design.md의 대기 분류(unknown=확정 상태 확인 대기, interrupted=중단)는 현재 모델에 대한 UI 분류 제안이다. 제품부 확인을 기록한 뒤 개발과 대기 검증에 적용한다. 실제 실행 대기 여부를 추정하지 않는다. 불수용 시 의미 결함으로 반환하고 기존 서버 계약 안에서 기준을 다시 확정한다.
- 한국어 역할 문구와 원본 역할 동시 표시를 확인한다. 기존 영문 배지에 한국어를 덧붙이는 방식과 미등록 역할의 원본 fallback을 공통 함수로 정의한다.
- 선택 자동 대체 제거, 실제 세션 응답 전이, 활동 페이지 상태 정리는 프런트엔드 수정 범위임을 확인한다. 서버·어댑터 변경으로 해결하지 않는다.

## 작업 순서와 개발 완료 조건

| 순서 | 개발팀 작업 | 완료 조건 | 관련 요구사항 |
| --- | --- | --- | --- |
| 1 | src/ 내부에 역할 표현·검색 정규화·상태 조건의 순수 계산 경계 정의 | 네 검색 필드 및 승인된 상태 분류가 하나의 규칙을 사용 | F01, F02, P03 |
| 2 | 전체 맵·상태 집계·일치 ID·조상 맥락 ID 계산 | 원본 불변, 고유 ID 집계, 부모 경로/순환 방어, 형제 제외 | F03, F04, P02 |
| 3 | 검색·상태·초기화·조건 요약·빈 상태 UI 연결 | 5개 단일 상태 선택, AND, M/N, 빈 세션과 결과 없음 구별 | F01–F05, F09 |

| 5 | 공급자/실제 세션 전이와 요청 무효화 정리 | 즉시 조건·선택 초기화, 늦은 응답 배제, 갱신 유지·선택 제거 안내 | F07, F08 |
| 6 | 반응형 배치·키보드·포커스·안전 표시 검토 | 좁은 화면 상세 유지, 네 필드 검색과 카드 표시 일치 | F09, P03, P04 |
| 7 | 개발 자체 검토와 기존 빌드 확인 후 QA 인계 | 변경 경계 검토와 결과 요약, 알려진 제약 기록 | P01–P06 |

변경 후보는 src/App.tsx, src/styles.css, 필요한 src/ 순수 계산 모듈이다. 공개 지원 의미에 설명이 필요한 경우 후속 개발에서 README.md의 UI 설명을 갱신한다. 설치·실행 설정·지원 저장 형식은 변경하지 않는다. 테스트 코드 책임은 QA에 있으며 개발은 제품 코드만 수정한다. 독립적인 좁은 탐색이나 반복 작업은 가능한 가장 저렴한 에이전트에 위임하되 수정 파일 책임을 분리한다.

## QA 인계 목록

다음은 후속 테스트 계획이며 실행 결과가 아니다. QA는 설치된 의존성과 workspace 안의 합성 자료만 사용한다. 실제 기록을 읽는 개발 서버를 검증 목적으로 실행하지 않는다. 브라우저 검증은 외부 요청 없이 가능한 합성 응답 하네스 및 단계별 실행 허용 범위 안에서 수행한다.

| 검증 묶음 | 필수 사례와 기대 결과 |
| --- | --- |
| 필드·정규화 | Build, dev-2, developer, 개발자 각각의 일치; 앞뒤 공백·대소문자; 내부 공백 유지; 미등록 역할 fallback |
| AND·상태 | developer+실패는 dev-2만 일치; 다섯 선택값 각각 확인; 중단/미확인은 승인된 분류대로 처리 |
| 계층·집계 | 테스트+대기는 qa-1과 두 맥락 조상, M=1/N=6; developer는 M=2/N=6과 맥락 포함 카드 4개; 숨긴 형제 제외 |
| 선택 | dev-1 선택 후 developer+실패에서도 상세 유지; 초기화 후 동일 선택; 맥락 선택 가능; 빈 결과에서도 상세 유지 |
| 빈 상태 | M=0/N=6 결과 없음과 초기화; N=0의 빈 세션; 로딩/오류 구별 |
| 범위·갱신 | 공급자 변경, 세션 변경, 응답이 실제 세션을 바꾼 경우 각각 초기화; 같은 세션 갱신 유지; 선택 제거 안내와 이전 상세 제거 |
| 요청·활동 페이지 | 이전 범위 응답·이전 선택의 늦은 활동 응답 무시; 선택 제거 시 cursor/활동 정리; 필터로 숨긴 상세의 페이지 처리 유지; 활동 개수가 N을 바꾸지 않음 |
| 접근성·배치 | 키보드로 모든 동작, 포커스 유지, 텍스트 상태·맥락·선택, 결과 알림, 좁은 화면 상세·컨트롤 가시성 |
| 개인정보·격리 | 새 API/서버 변경 없음, 검색어 비영구성·추가 요청 없음, 공개 필드 외 검색 없음, 합성 민감 표식 비노출, 기존 격리 검증 유지 |

prototype.md의 개념적 상태 집계(진행 중 2/완료 1/실패 1/대기 2)는 실제 합성 모델로 변환한 뒤 검증한다. 중단을 추가한 자료에서도 N은 모든 고유 에이전트를 포함하고 대기·실패에 임의 합산하지 않는다. 중복 ID·누락 부모·순환 자료는 중복 집계나 무한 렌더링을 발생시키지 않아야 한다.

QA는 npm test(기존 어댑터 회귀 검증), npm run build(타입 검사·번들), 추가 필터 검증을 맡는다. 개발은 QA가 보고한 결함을 수정하고 테스트를 약화하지 않는다. package.json에 test:browser가 있으나 현재 해당 실행 파일은 확인되지 않았으므로 스크립트 존재만으로 브라우저 검증을 완료했다고 보고하지 않는다. QA가 테스트 단계에서 허용된 하네스를 준비하고 실행 가능 여부를 보고한다.

프런트엔드 스냅샷에 프로젝트 필드가 없으므로 다른 프로젝트 루트 배제는 기존 어댑터의 합성 격리 테스트와 변경 경계 검토로 확인한다. UI 테스트에서는 없는 노드·외부 부모를 검색이나 맥락 확장으로 가져오지 않는 것을 검증한다. 기존 server/ 테스트가 실패하면 개발팀에 결함을 반환하고 이 작업 범위에서 어댑터를 임의 수정하지 않는다.

## 결함 반환과 출시 게이트

QA 결함 보고는 요구사항 ID, 합성 재현 절차, 기대/실제 동작, 영향, 개발 반환 여부를 포함한다. 비공개 추론·실제 기록·원시 명령 출력·API 응답은 기록하지 않는다. 개발 수정 후 QA는 동일 재현 절차와 수정 영향에 맞는 회귀 항목을 재검증한다. 검증 기준이나 기대값을 제품 동작에 맞춰 약화하지 않는다.

QA 인계의 통과 기준은 F01–F09와 P01–P06의 충족, 대기 의미 확정, 중요한 결함 해결, 타입/빌드 및 필요한 회귀 검증 결과 기록이다. 실행하지 못한 검증은 미실행과 이유를 명시하며 통과로 취급하지 않는다. 제품/QA 검토 및 출시 승인이 완료된 뒤 운영팀이 기존 설정의 로컬 배포와 확인을 진행한다.

이 격리 design 단계에서는 배포, 네트워크 요청, 의존성 설치, Paperclip 호출, 커밋, push를 수행하지 않는다. 후속 단계도 해당 단계의 명시된 허용 범위를 우선한다.
