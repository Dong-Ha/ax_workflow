# 로컬 출시 계획

현재 단계: release. 계획 작성 완료이며 패키징·배포·상태 점검·출시 관찰·롤백은 NOT RUN이다. 컨트롤러가 후속 허용 실행에서 패키징과 실행 점검을 담당한다. 이번 단계는 release-plan.md와 release-checklist.md만 작성한다.

## 입력과 계약 충돌

requirements-amendment.md, requirements.md, prototype.md, design.md, test-plan.md, improvement-request.md, test-environment.md, deployment-plan.md와 기존 출시 문서를 읽었다. 현재 승인 입력은 approval.json, release-notes.md, system.json 및 verified-AXM-44.json이다. operator-review-AXM-43.md의 이전 승인 보류와 검증기 보강 기록도 검토했다. 이전 명세, 구현·QA·승인·출시·운영 검토·컨트롤러 보고서는 보존하며 deployment-plan.md는 수정하지 않는다.

초기 명세·설계·테스트 계획의 다섯 상태, 대기/완료 표현과 기본 선택 설명은 현재 계약과 충돌한다. 읽기 전용 requirements-amendment.md와 현재 계약을 적용한다. 상태는 all/전체, inProgress/진행 중, completed/턴 완료, failed/실패, interrupted/중단, unknown/상태 미확인이다. unknown을 대기로 해석하지 않고 종료 기록 없이 턴 완료를 추정하지 않는다. 공급자·세션 변경 후 자동 선택하지 않는다. F01–F09/P01–P06을 축소하지 않는다.

현재 approval.json은 approved=true이며 release-notes.md는 이동 위치 후속 범위를 포함한 현재 검증 후보의 출시를 승인한다. system.json과 verified-AXM-44.json의 실행·이슈 연결, 검사 목록 및 최종 pass가 일치하고 findings는 비어 있다. 이는 보존된 증거 검토이며 이번 단계에서 테스트를 재실행하지 않았다. 이전 verified-AXM-43.json의 단계 pass만으로 현재 후보 승인이나 배포를 판단하지 않는다. release-notes.md의 독립 컨트롤러 회귀·빌드·브라우저·고정 그래프·계층·보강 이동 통과 보고와 샌드박스 자체 미검증을 구분한다.

기존 정식 브라우저 결과는 지정 스키마, 23개 pass 시나리오 및 screenshotSaved=true를 확인했다. 스크린샷의 새 생성이나 기능 재검증을 주장하지 않는다. 대형 트리 여섯 사례와 고정 그래프 비교, 이동 여섯 사례 통과는 release-notes.md의 승인 검토 결과로 인용한다. 실행 전 동일 후보 연결을 확인해야 한다.

improvement-request.md의 현재 후속 범위는 검색 결과 이동 위치 표시다. 필터 영역의 role=status, aria-label=일치 항목 이동 위치, aria-live=polite 요소에 이동 위치 k / N을 표시한다. N은 실제 일치 수이며 맥락 카드·선택 상세를 포함하지 않는다. 이동 전과 검색·상태·초기화·공급자·세션 변경 후 k=0이다. 다음·이전·순환 후 k는 화면 순서 기준 1부터 시작한다. 결과 없음은 이동 위치 0 / 0이다. 같은 세션 갱신에서 현재 항목이 여전히 일치하면 유지하고, 재정렬 시 같은 항목의 위치를 재계산한다. 더 이상 일치하지 않으면 k=0으로 초기화하고 다른 항목으로 자동 이동하거나 자동 초점을 옮기지 않는다. 현재 항목의 검색 불일치는 스냅샷 삭제와 별개로 관찰한다.

기존 이전/다음 버튼·단축키·초점·스크롤·선택 및 상세 유지·개수·실제 부모·개인정보 계약과 대형 트리 검증을 유지한다. 실제 일치 항목만 양방향 순환하고 다음은 첫 항목, 이전은 마지막 항목부터 시작한다. 초기화 후 결과가 있으면 이동 가능하며 결과가 없으면 이동 불가다. operator-review-AXM-43의 이전 범위 공백은 최신 승인 노트와 verified-AXM-44의 보강된 정식 검증으로 해소되었다고 보고되며, 이전 보고는 수정하지 않는다. 보강 이동 검증은 실제 렌더링 갱신, 재정렬, 현재 항목의 검색 불일치 후 위치 0과 자동 초점 이동 방지를 포함한다.

deployment-plan.md의 BLOCKED는 환경 단계 당시 판정으로 보존한다. 기존 출시 문서의 verified-AXM-36/37과 과거 후보 연결, delivery-review.md의 역사적 전달 결과는 현재 후보의 배포 증거가 아니다. 이전 실패 및 자체 실행 제약도 그대로 보존한다. 현재 승인은 후보 한정이며 패키징·배포 완료나 복구 대상 확보를 의미하지 않는다.

## 버전 기록과 실행 게이트

운영팀과 컨트롤러는 실행 전에 다음 연결을 불변 기록으로 확보한다. 미확보 값은 미확보로 두며 이 문서에서 임의 버전·체크섬을 생성하지 않는다.

| 항목 | 기록 및 현재 상태 |
| --- | --- |
| 승인 근거 | approval.json, release-notes.md; 이동 위치 후속 범위를 포함한 현재 후보 한정 승인 확인 |
| 검증 연결 | system.json/verified-AXM-44.json의 시스템 실행 df3dd65c-d6a8-4703-a9ce-50ce59e1954e, 이슈 1bb04d77-74f9-4f95-9869-7958f3e24573과 approval.json/release-notes.md를 연결한다. 실행 ID를 제품 버전으로 대체하지 않는다. |

제품부 → 개발팀 → 테스트팀 → 운영팀 순서를 유지한다. 기존 승인 증거와 실제 후보 동일성을 확인하고 필수 검증 및 미해결 차단/주요 결함 유무를 재확인한다. 승인 뒤 제품 후보가 바뀌면 개발 수정 → QA 동일 사례와 영향 범위 재검증 → 제품·QA 검토 → 새 출시 승인으로 돌아간다. QA는 제품 코드를 수정하거나 테스트를 약화하지 않는다.

컨트롤러가 복구 대상과 후보 연결을 확보한 뒤 별도 허용 실행에서 승인 후보를 패키징하고 체크섬을 연결한다. 패키지 불일치, 승인 후보 연결 불명, 복구 대상 부재 또는 검증 공백이 있으면 배포를 시작하지 않는다. 현 상태는 문서 인계 준비 완료, 후보·패키지·복구 연결 확인 대기이며 출시 완료가 아니다.

## 출시 관찰

컨트롤러가 승인된 로컬 합성 환경에서 시작·종료 상태 점검을 수행하고 운영팀은 안전한 요약만 기록한다. 관찰 기간은 컨트롤러 실행 계획에 시작 전에 명시한다. 이번 단계는 서버 시작이나 네트워크 점검을 수행하지 않는다.

| 관찰 항목 | 통과 조건 |

| 시작 | 승인 후보와 실행 패키지 ID·체크섬 일치, localhost 전용, 상태 점검과 화면 로드 성공 |

관찰 종료는 모든 항목 통과, 같은 범위 갱신 최소 한 번, 공급자·세션 각각 전환, 선택 삭제 확인, 대형 트리 여섯 사례와 데스크톱·좁은 화면의 일치 항목 이동과 위치 표시·실제 갱신·재정렬·검색 불일치 전이 확인, 미해결 주요/차단 결함 없음 및 종료 상태 점검 성공을 요구한다. 기간 경과만으로 성공을 판정하지 않는다. 실패하면 아래 순서로 롤백한다.

## 롤백 순서

1. 상태 점검 실패, 패키지 불일치, 계약 위반, 민감 노출 또는 프로젝트 혼입 시 출시 완료 판정을 중단하고 실패 후보·결함 ID와 안전한 영향 요약만 기록한다.
2. 컨트롤러가 실패 후보의 로컬 실행과 관찰을 중지한다.
3. 사전에 확보한 이전 검증 패키지 ID·체크섬·호환성을 확인한다. 대상이 없거나 불일치하면 중지 상태를 유지하고 운영 장애로 보고한다. 임의 버전으로 대체하지 않는다.
4. 운영팀이 후속 허용 범위에서 기존 로컬 절차로 이전 UI 패키지를 복원하고 컨트롤러가 시작한다. 원본 기록·설정·인증 파일은 복구하지 않으며 데이터 마이그레이션, 서버/어댑터 변경, 의존성 설치를 하지 않는다. 브라우저를 복구 버전으로 새로 로드한다.
5. 컨트롤러 상태 점검과 합성 핵심 조작으로 복구 버전, 화면 로드, 범위 전환의 이전 상세 비노출과 개인정보 경계를 확인한다. 실패하면 중지 상태를 유지하고 운영팀에 에스컬레이션한다.
6. 실패/복구 후보·패키지 연결과 복구 판정, 남은 영향 및 개발 반환을 기록한다. 개발 수정 → QA 동일 사례/영향 범위 재검증 → 제품·QA 검토 → 재승인 → 컨트롤러 재패키징 후 재출시한다.

보고에는 비공개 추론, 환경 값, 인증 자료, 원시 명령 출력이나 API 응답을 넣지 않는다. QA findings는 비어 있지 않은 안전 문자열 또는 비어 있지 않은 문자열 title/summary 필드만 가진 객체로 제한한다. 브라우저 결과는 지정된 verdict/screenshotSaved/results(name/verdict/finding) 스키마와 안전 요약을 유지하고 기존 QA 보고를 덮어쓰지 않는다.
