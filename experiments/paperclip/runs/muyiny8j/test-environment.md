# 테스트 환경 준비 및 버전 기록

현재 단계: environment. 운영팀의 준비 문서이며 실행 결과가 아니다. requirements-amendment.md, requirements.md, prototype.md, design.md, test-plan.md 및 implementation.md를 검토했다. 이번 단계는 이 문서와 deployment-plan.md 작성에 한정한다. 앱·서버·어댑터·테스트 코드를 변경하거나 테스트 서버 시작, 패키징, 배포, 상태 점검을 실행하지 않았다.

## 계약 정합성과 인계 결함

최신 제품 계약과 requirements-amendment.md를 판정 기준으로 사용한다. 기존 문서는 수정하지 않고 다음 충돌을 개발·제품·QA에 인계한다.

| 항목 | 발견 사항 | 출시 전 필요한 조치 |
| --- | --- | --- |
| E01 상태 계약 | requirements/prototype/design 및 개발 규칙·테스트 계획에는 대기 포함 5개 선택이나 이전 의미 차단 기록이 남아 있다. implementation.md도 5개 필터와 unknown의 대기 분류를 구현했다고 보고한다. | 개발팀이 6개 키와 정확한 표시 문구를 구현하고 제품부가 관련 명세를 정합화한다. unknown은 대기로 해석하지 않는다. QA가 단위·브라우저 양쪽에서 전부 재검증한다. |
| E02 선택 계약 | test-plan.md의 C02는 이전 계약에 기본 선택 허용이 있었다고 기록한다. 현재 계약은 공급자·세션 변경 시 자동 선택을 허용하지 않는다. | 필터·이전 상세 제거와 새 세션 선택 안내를 각각 검증하고 기본 선택을 도입하지 않는다. |
| E03 실행 증거 | implementation.md는 브라우저 테스트 미작성·미실행 및 전체 npm test 실패를 보고한다. 일부 단위·회귀·빌드 통과는 이전 단계의 보고다. | QA가 현재 버전의 필수 테스트 증거를 확보한다. 금지된 네트워크·Paperclip 실행을 포함하는 테스트는 강행하지 않고 실행 제약과 검증 공백을 기록한다. 테스트를 약화하거나 미실행을 PASS로 처리하지 않는다. |

E01은 현재 승인 계약으로 기대값이 확정되었으나 구현·문서 정합화와 재검증이 남아 있다. 이전 대기 의미 제안을 출시 근거로 사용하지 않는다. 현재 출시 준비 판정은 BLOCKED이며 새 테스트 실행 결과는 NOT RUN이다.

## 준비 책임 및 실행 경계

- 제품부: 계약 정합화와 수용 기준 검토. 개발팀: E01 및 QA 결함 수정. 테스트팀: 테스트·합성 하네스·독립 판정과 재검증. 운영팀: 버전 및 승인 증거 연결, 관찰·복구 계획.
- 컨트롤러: 허용된 후속 실행에서 테스트 서버 시작·종료, 패키징, 상태 점검을 소유한다. 이 문서의 계획은 현재 실행 권한을 확대하지 않는다.
- Node.js 24 이상과 기존 설치 의존성을 전제로 한다. 컨트롤러가 런타임 호환성, 설치된 테스트 도구와 브라우저 실행 가능 여부를 확인한다. 부족하면 준비 미완료로 기록하며 설치·다운로드·외부 요청으로 보완하지 않는다.
- 모든 임시 자료와 허용된 출력은 supplied workspace 내부에 둔다. 실제 기록·자격 증명·환경 값·부모 디렉터리는 사용하지 않는다. 합성 스냅샷을 메모리에서 제공하고 브라우저 fetch는 인메모리 대체한다. 실제 API나 외부 네트워크로 우회하지 않는다.
- 서버·어댑터·인증·API 동작·원본 파일은 변경하지 않는다. 개인정보 검증은 합성 표식으로 수행하고 보고서에는 기대/실제 동작 요약만 남긴다.

## 필수 합성 자료와 검증 범위

prototype.md의 6개 에이전트 관계를 유지하되 qa-1은 interrupted, ops-1은 unknown으로 명시한 수정 합성 자료를 QA가 준비한다. review-1은 completed다. 전체 N=6, 상태별 수는 inProgress=2, completed=1, failed=1, interrupted=1, unknown=1이다. 이 매핑은 테스트 입력이며 실제 상태를 추정하는 규칙이 아니다.

| 상태 키 | 정확한 표시 | 상태만 선택할 때 일치 수 |
| --- | --- | --- |
| all | 전체 | 6 |
| inProgress | 진행 중 | 2 |
| completed | 턴 완료 | 1 |
| failed | 실패 | 1 |
| interrupted | 중단 | 1 |
| unknown | 상태 미확인 | 1 |

생성 단위 테스트와 브라우저 테스트는 각각 모든 키와 표시 문구를 확인한다. 이름·ID·원본 역할·한국어 표시 역할 검색, 정규화와 검색/상태 AND, 일치 후손 및 비일치 조상 맥락, 숨긴 형제 제외, 일치/전체 집계와 필터 초기화를 포함한다. 집계는 항상 전체 스냅샷을 기준으로 하며 맥락 카드·상세·활동 페이지 수를 더하지 않는다.

두 검증 층 모두 공급자 변경과 세션 변경을 별개 사례로 실행한다. 활성 필터와 선택을 준비한 후 즉시 필터·이전 선택/상세/활동을 제거하고 새 세션 선택 안내가 나타나는지 확인한다. 새 범위에서 같은 ID를 재사용하고 이전 응답을 지연해도 상세가 복원되거나 자동 선택되지 않아야 한다. 선택 삭제는 보이는 선택과 필터로 숨긴 선택에서 각각 이전 상세 제거 및 이용 불가 안내를 확인한다. 같은 세션 필터 변경은 유효한 선택 상세를 유지해야 한다.

빈 결과와 빈 세션, 로딩·오류의 구별, 같은 범위 갱신, 새 요청의 이전 턴 결과 제외, 종료 기록 없는 완료 추정 금지, 키보드·포커스·접근성·좁은 화면도 F01–F09에 따라 검증한다. P01–P06의 프로젝트 격리·실제 부모·민감 표식 비노출·safeText 경로·검색 비영구성·추가 요청 없음 및 페이지 처리 회귀를 유지한다.

QA 실행 순서는 계약/합성 자료 검토 → 단위 → 브라우저 → 허용된 회귀와 타입 검사 → 변경 경계 검토다. 패키징은 컨트롤러 책임이며 여기서 npm run build를 실행하지 않는다. 불가능한 검증은 BLOCKED 또는 NOT RUN과 이유를 기록한다. 결함은 개발팀에 반환하고 수정 버전에서 같은 재현 사례와 영향 범위를 재검증한다.

## 버전 기록 양식

컨트롤러와 QA는 실제 준비·실행 후 다음 항목을 연결한다. 현재 값은 모두 미확보이며 임의 버전이나 성공 결과를 만들지 않는다. 격리 지침에 따라 커밋·push는 수행하지 않는다.

| 기록 항목 | 기록 기준 |
| --- | --- |
| 후보 식별자 | 기존 리비전 식별자 또는 컨트롤러가 부여한 불변 후보 ID, 작성 시각, 변경 파일 목록 |
| 계약 기준 | 최신 제품 계약과 요구사항 보완의 식별자/문서 체크섬 |
| 실행 도구 | 사용한 Node·패키지 관리자·브라우저/테스트 도구 버전과 의존성 잠금 파일 체크섬; 환경 변수 값은 제외 |
| 검증 연결 | 후보 ID별 단위·브라우저·회귀·타입/패키징 판정과 QA 보고서 위치, 결함 및 재검증 상태 |
| 패키지 연결 | 컨트롤러가 생성한 패키지 ID·체크섬과 해당 후보 ID; 아직 패키지 없음 |
| 승인/복구 연결 | 제품·QA·출시 승인 기록, 이전 검증된 패키지 ID와 복구 대상; 아직 승인 및 복구 대상 미확보 |

보고서는 결과 요약만 포함하며 원시 subprocess 출력·API 응답·환경 값·인증 자료·비공개 추론을 포함하지 않는다. 이 문서 작성은 테스트 환경 가동이나 기능 검증 완료를 의미하지 않는다.
