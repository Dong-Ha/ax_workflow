# 로컬 출시 계획

현재 단계: release. 계획 작성 완료이며 패키징·배포·상태 점검·출시 관찰·롤백은 NOT RUN이다. 컨트롤러가 후속 허용 실행에서 패키징과 실행 점검을 담당한다. 이번 단계는 release-plan.md와 release-checklist.md만 작성한다.

## 입력과 계약 충돌

requirements-amendment.md, requirements.md, prototype.md, design.md, test-plan.md, test-environment.md, deployment-plan.md, approval.json, release-notes.md, system.json, verified-AXM-19.json, verified-AXM-20.json 및 agent-filter-browser-results.json을 검토했다. 기존 출시 계획·체크리스트도 검토했다. deployment-plan.md를 포함한 이전 산출물은 보존한다.

이전 명세·설계·테스트 계획의 다섯 상태, 대기/완료 문구와 기본 선택 설명은 현재 계약과 충돌한다. 읽기 전용 requirements-amendment.md 및 현재 계약을 적용한다. 상태는 all/전체, inProgress/진행 중, completed/턴 완료, failed/실패, interrupted/중단, unknown/상태 미확인이다. unknown을 대기로 해석하지 않고 종료 기록 없이 완료를 추정하지 않는다. 공급자·세션 변경 후 자동 선택하지 않는다. F01–F09/P01–P06을 축소하지 않는다.

deployment-plan.md의 BLOCKED는 환경 단계 당시 판정이다. 이후 approval.json과 release-notes.md는 현재 시스템 후보 한정 승인을 기록한다. system.json과 verified-AXM-19.json의 시스템 실행 연결 및 독립 컨트롤러 회귀·빌드·브라우저·고정 그래프 검증 통과를 확인했다. verified-AXM-20.json은 현재 승인 단계 통과 기록이다. 정식 브라우저 결과는 지정 스키마를 만족하고 23개 시나리오 모두 pass이며 screenshotSaved=true와 기존 PNG 파일 존재를 확인했다. 단위 24개 통과는 release-notes.md에 기록된 검토 결과이며 이번 단계에서 재실행하지 않았다.

샌드박스 자체의 전체 회귀·브라우저 미검증은 보존하며 새 실행 통과로 주장하지 않는다. 기존 출시 문서의 verified-AXM-14/15 및 이전 실행 연결은 현재 승인 근거로 사용하지 않는다. 보호된 명세의 충돌을 삭제하거나 수정하지 않고 현재 계약 및 요구사항 보완을 우선한다. 승인은 배포 완료나 복구 대상 확보를 의미하지 않는다.

## 버전 기록과 실행 게이트

운영팀과 컨트롤러는 실행 전에 다음 연결을 불변 기록으로 확보한다. 미확보 값은 미확보로 두며 이 문서에서 임의 버전·체크섬을 생성하지 않는다.

| 항목 | 기록 및 현재 상태 |
| --- | --- |
| 승인 근거 | approval.json, release-notes.md, verified-AXM-20.json; 현재 후보 한정 승인 확인 |
| 검증 연결 | 시스템 실행 24278a4a-f0dc-4d0e-9acd-49516c35119d 및 system.json/verified-AXM-19.json; 승인 단계 실행 64f288e2-c9b4-487b-98f9-f15c0a581146 및 verified-AXM-20.json. 실행 ID를 제품 버전으로 대체하지 않는다. |
| 후보 버전 | 컨트롤러 불변 후보 ID 또는 기존 리비전, 작성 시각, 변경 파일 목록과 승인 후보의 동일성; 현재 독립 버전 연결 미확보 |
| 계약 기준 | 현재 제품 계약, requirements-amendment.md 식별자·체크섬; 체크섬 미확보 |
| 도구·호환성 | Node.js 24 이상, 패키지 관리자·브라우저·테스트 도구 버전, 잠금 파일 체크섬; 이번 단계 미확인 |
| 후보 패키지 | 컨트롤러 생성 패키지 ID·체크섬과 후보 ID 연결; 미생성 |
| 복구 버전 | 이전 검증 패키지 ID·체크섬, 호환성 및 복원 가능 여부; 미확보 |
| 실행 결과 | 승인·시작·관찰 종료 시각, 항목별 판정, 결함 ID, 롤백 여부와 복구 판정; NOT RUN |

제품부 → 개발팀 → 테스트팀 → 운영팀 순서를 유지한다. 기존 승인 증거와 실제 후보 동일성을 확인하고 필수 검증 및 미해결 차단/주요 결함 유무를 재확인한다. 승인 뒤 제품 후보가 바뀌면 개발 수정 → QA 동일 사례와 영향 범위 재검증 → 제품·QA 검토 → 새 출시 승인으로 돌아간다. QA는 제품 코드를 수정하거나 테스트를 약화하지 않는다.

컨트롤러가 복구 대상과 후보 연결을 확보한 뒤 별도 허용 실행에서 승인 후보를 패키징하고 체크섬을 연결한다. 패키지 불일치, 승인 후보 연결 불명, 복구 대상 부재 또는 검증 공백이 있으면 배포를 시작하지 않는다. 현 상태는 문서 인계 준비 완료, 후보·패키지·복구 연결 확인 대기이며 출시 완료가 아니다.

## 출시 관찰

컨트롤러가 승인된 로컬 합성 환경에서 시작·종료 상태 점검을 수행하고 운영팀은 안전한 요약만 기록한다. 관찰 기간은 컨트롤러 실행 계획에 시작 전에 명시한다. 이번 단계는 서버 시작이나 네트워크 점검을 수행하지 않는다.

| 관찰 항목 | 통과 조건 |
| --- | --- |
| 시작 | 승인 후보와 실행 패키지 ID·체크섬 일치, localhost 전용, 상태 점검과 화면 로드 성공 |
| 상태 | 여섯 키와 정확한 문구 전부 일치; unknown 대기 추정 없음 |
| 검색·계층 | 이름·ID·원본 역할·한국어 역할 검색, 검색/상태 AND, 일치 후손과 비일치 실제 조상 맥락, 숨긴 형제 제외 |
| 집계·빈 상태 | 일치 M/전체 N과 상태 집계는 전체 스냅샷 기준; 맥락·상세·활동 페이지를 가산하지 않음; 초기화·일치 없음·빈 세션 구별 |
| 선택·범위 | 필터가 숨긴 유효 선택 상세 유지; 공급자와 세션 각각 변경 시 필터·이전 선택/상세/활동 제거, 새 세션 선택 안내, 자동 선택 없음 |
| 삭제·갱신 | 보이는/숨긴 선택 삭제 시 이용 불가 안내와 이전 상세 제거; 같은 범위 갱신, 늦은 응답 차단, 새 요청에 이전 턴 결과 없음 |
| 조작·안전 | 키보드·포커스·좁은 화면·텍스트 안내; 실제 부모·프로젝트 경계, safeText 경로, 합성 민감 표식 비노출, 원본 쓰기·추가 검색 요청·영구 검색 저장 없음 |

관찰 종료는 모든 항목 통과, 같은 범위 갱신 최소 한 번, 공급자·세션 각각 전환, 선택 삭제 확인, 미해결 주요/차단 결함 없음 및 종료 상태 점검 성공을 요구한다. 기간 경과만으로 성공을 판정하지 않는다. 실패하면 아래 순서로 롤백한다.

## 롤백 순서

1. 상태 점검 실패, 패키지 불일치, 계약 위반, 민감 노출 또는 프로젝트 혼입 시 출시 완료 판정을 중단하고 실패 후보·결함 ID와 안전한 영향 요약만 기록한다.
2. 컨트롤러가 실패 후보의 로컬 실행과 관찰을 중지한다.
3. 사전에 확보한 이전 검증 패키지 ID·체크섬·호환성을 확인한다. 대상이 없거나 불일치하면 중지 상태를 유지하고 운영 장애로 보고한다. 임의 버전으로 대체하지 않는다.
4. 운영팀이 후속 허용 범위에서 기존 로컬 절차로 이전 UI 패키지를 복원하고 컨트롤러가 시작한다. 원본 기록·설정·인증 파일은 복구하지 않으며 데이터 마이그레이션, 서버/어댑터 변경, 의존성 설치를 하지 않는다. 브라우저를 복구 버전으로 새로 로드한다.
5. 컨트롤러 상태 점검과 합성 핵심 조작으로 복구 버전, 화면 로드, 범위 전환의 이전 상세 비노출과 개인정보 경계를 확인한다. 실패하면 중지 상태를 유지하고 운영팀에 에스컬레이션한다.
6. 실패/복구 후보·패키지 연결과 복구 판정, 남은 영향 및 개발 반환을 기록한다. 개발 수정 → QA 동일 사례/영향 범위 재검증 → 제품·QA 검토 → 재승인 → 컨트롤러 재패키징 후 재출시한다.

보고에는 비공개 추론, 환경 값, 인증 자료, 원시 명령 출력이나 API 응답을 넣지 않는다. QA findings는 비어 있지 않은 안전 문자열 또는 비어 있지 않은 문자열 title/summary 필드만 가진 객체로 제한한다. 브라우저 결과는 지정된 verdict/screenshotSaved/results(name/verdict/finding) 스키마와 안전 요약을 유지하고 기존 QA 보고를 덮어쓰지 않는다.
